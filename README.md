# Puisabpak NCR / CAPA eForm

ระบบบันทึกรายงานความไม่สอดคล้อง (NCR) และ CAPA ของโรงงานปุยแสบปาก ใช้คู่กับ SOP-QA-001

- `src/` หน้าจอ (React + Vite) ขึ้นใช้งานบน Cloudflare Pages
- `worker/` หลังบ้าน (Cloudflare Worker + ฐานข้อมูล D1 ชื่อ `puisabpak-ncr`)

## สิ่งที่ระบบควบคุม

| เรื่อง | การทำงาน |
| --- | --- |
| การเข้าใช้ | ต้องล็อกอิน บัญชีล็อก 15 นาทีเมื่อใส่รหัสผิด 5 ครั้ง เซสชันหมดอายุใน 12 ชั่วโมง |
| บทบาท | ผู้จัดการ QA, หัวหน้าทีมความปลอดภัยอาหาร (FSTL), QC, หัวหน้าแผนก, ดูอย่างเดียว |
| เลขที่เอกสาร | ระบบออกเอง `NCR-ปปดด-ลำดับ` และ `CAPA-ปปดด-ลำดับ` แก้ไขไม่ได้ |
| การตัดสินใจและทวนสอบ | เฉพาะผู้จัดการ QA และ FSTL ระบบบันทึกชื่อผู้ทำและเวลาให้ |
| การปิด NCR | เฉพาะผู้จัดการ QA และต้องมีข้อมูลครบ เมื่อปิดแล้วแก้ไขไม่ได้ เปิดใหม่ได้โดยระบุเหตุผล |
| ประวัติการแก้ไข | บันทึกทุกการเปลี่ยนแปลง ไม่มีคำสั่งลบ |
| ลิงก์ผู้ส่งมอบ | เปิดได้เฉพาะเอกสารฉบับเดียว เห็นและกรอกได้เฉพาะช่องที่กำหนด หมดอายุ 14 วัน |

## การติดตั้งครั้งแรก

1. ที่ GitHub ของ repository นี้ ไปที่ Settings → Secrets and variables → Actions แล้วเพิ่ม secret 3 ตัว
   - `CLOUDFLARE_API_TOKEN` โทเคนของ Cloudflare ที่มีสิทธิ์แก้ไข Workers, Pages และ D1
   - `CLOUDFLARE_ACCOUNT_ID` รหัสบัญชี Cloudflare
   - `SETUP_KEY` รหัสลับที่ตั้งเอง ยาวอย่างน้อย 20 ตัว ใช้ครั้งเดียวตอนสร้างบัญชีผู้จัดการ QA คนแรก
2. ส่งโค้ดขึ้น branch `main` ระบบจะทดสอบและ deploy เอง (ดูผลที่แท็บ Actions)
3. เปิด `https://puisabpak-ncr.pages.dev/setup` กรอก Setup key แล้วสร้างบัญชีผู้จัดการ QA
4. เข้าสู่ระบบ แล้วเพิ่มผู้ใช้คนอื่นที่เมนูบัญชี → จัดการผู้ใช้

หาก Cloudflare ตั้งชื่อเว็บต่างจาก `puisabpak-ncr.pages.dev` ให้แก้ `ALLOWED_ORIGINS` ใน `worker/wrangler.toml` ให้ตรง
หากที่อยู่ของ Worker ต่างจากที่ตั้งไว้ ให้แก้ `VITE_API_URL` ใน `.github/workflows/deploy-pages.yml`

## ข้อมูลที่ต้องปรับให้ตรงกับโรงงาน

- `src/config.js` ชื่อบริษัทและรหัสแบบฟอร์ม
- `src/data/masterData.js` ขั้นตอนการผลิต พารามิเตอร์ รายชื่อผู้ส่งมอบ และผลิตภัณฑ์ (รายการปัจจุบันเป็นร่างเริ่มต้น)

## PSP QUALITY APP (บันทึกการเฝ้าระวังจุดควบคุม)

เมนู PSP QUALITY APP (`/qa`) ใช้บัญชีผู้ใช้และฐานข้อมูลเดียวกับ NCR

| เรื่อง | การทำงาน |
| --- | --- |
| ทะเบียนจุดควบคุม | ตาม QP-HA-001 HACCP Manual Rev.01 (ร่าง) แผ่นงาน 7: CCP-01, CCP-02 และ OPRP-01 ถึง 06 ทุกจุดเป็นสถานะ "รอ validate" ผู้จัดการ QA / FSTL กำหนดประเภท เกณฑ์ และผลิตภัณฑ์ได้เอง อนุมัติได้เมื่อจัดประเภทแล้วและทุกค่าที่วัดมีเกณฑ์ |
| เวอร์ชันเกณฑ์ | เปลี่ยนเกณฑ์ ผลิตภัณฑ์ ประเภท หรือสถานะ แล้วขึ้นเวอร์ชันใหม่ บันทึกเดิมยังอ้างเวอร์ชันที่ใช้ตอนตรวจ |
| การตัดสินผล | หลังบ้านเป็นผู้ตัดสินผ่าน / ไม่ผ่าน จากเกณฑ์ที่ใช้อยู่ ผู้ตรวจคือบัญชีที่เข้าสู่ระบบ |
| เมื่อไม่ผ่านเกณฑ์ | บันทึกผลเป็นไม่ผ่าน และเปิด NCR ในคราวเดียวกันเมื่อ `AUTO_NCR_PRODUCTION = "on"` ใน `worker/wrangler.toml` (CCP เปิดเป็น Critical อื่น ๆ เป็น Major) ช่วงทดลองระบบตั้งเป็น `"off"`: บันทึกจุดควบคุม FM-QC-002 FM-QC-005 FM-QC-006 ไม่เปิด NCR เอง (การตรวจรับวัตถุดิบยังออก NC/NCR ตามเดิม) บันทึกที่ไม่ผ่านยังกันการปล่อยสินค้าจนกว่าจะมีบันทึกใหม่ที่ผ่าน |
| บันทึก | แก้ไขหรือลบไม่ได้ ดูย้อนหลังและดาวน์โหลด CSV ได้ที่ `/qa/records` |
| FG Release (`/qa/release`) | ปล่อยสินค้าได้เมื่อจุดควบคุมที่ตั้งเป็น "ต้องผ่านก่อนปล่อย" มีบันทึกล่าสุดของ Batch ที่ผ่าน (หรือ NCR ที่ปิดโดยตัดสินปล่อย) ไม่มี NCR ค้างของ Batch และยืนยันการตรวจและวันที่ครบ (ล็อตวัตถุดิบไม่บังคับ) ตัดสินได้เฉพาะ QA Manager / FSTL หลังบ้านตรวจซ้ำทุกครั้งและเก็บสถานะ ณ เวลาตัดสิน Batch หนึ่งปล่อยได้ครั้งเดียว ผลิตภัณฑ์ที่ยังไม่มีจุดควบคุมในแผน HACCP ปล่อยไม่ได้ |
| ตรวจรับวัตถุดิบ (`/receiving/`) | แอป FM-QC-001 อยู่ในเว็บเดียวกับ PSP QUALITY APP ใช้การเข้าสู่ระบบเดียวกัน (ไฟล์ `public/receiving/index.html`) ที่อยู่เดิม `puisabpak-receiving…workers.dev` ยังเปิดได้เพื่อให้เครื่องที่มีรายการค้างส่งส่งให้ครบ แล้วพาไปที่อยู่ใหม่เอง |
| สูตรการผลิต (`/qa/formulas`) | น้ำหนักวัตถุดิบต่อ 1 ชุด ตั้งต้นจากใบชั่ง (PD_03 เดิม) รอบล่าสุดของ 10 ผลิตภัณฑ์ (สถานะรอยืนยัน) QA แก้ไข กำหนด Tolerance (±%) แล้วอนุมัติ ทุกการแก้ไขขึ้นเวอร์ชันและเก็บประวัติ |
| บันทึกการชั่งวัตถุดิบ FM-QC-004 (`/qa/weigh`) | ต่อ Batch: ทุกรายการตามสูตร เลือก LOT จากใบตรวจรับ FM-QC-001 (ไม่บังคับ) กรอกน้ำหนักชุดที่ 1–12 ผู้ชั่งจากบัญชีที่ล็อกอิน นอก Tolerance หรือมีวัตถุดิบนอกสูตร ต้องให้หัวหน้างาน / QA บันทึกผลการประเมิน Batch หนึ่งชั่งได้ครั้งเดียว พิมพ์ A4 ตามฟอร์ม FG Release ดึงล็อตจากบันทึกนี้ และสอบย้อนกลับค้นเจอ Batch ที่ใช้ล็อต |
| แบบฟอร์มควบคุมการผลิต FM-QC-002 (`/qa/prodctl`) | ต่อ Batch (เลือกจาก Batch ที่ชั่ง FM-QC-004 แล้วได้): คั่ว/ทอด/เจียว กระเทียม หอม พริก-เห็ด-หมูบด (น้ำหนักก่อน-หลัง อุณหภูมิ เวลา) บด ผัด/กวน และพักเย็น กลุ่ม A บันทึก CCP-01 แบบเต็ม (เวลาที่ถึง 85°C เวลาสิ้นสุด อุณหภูมิแกนกลางทุก 30 นาที เทอร์โมมิเตอร์) และ OPRP-05 (อุณหภูมิขณะบรรจุ เวลาจนปิดฝา แช่เย็น) ระบบสร้างบันทึก CCP-01 / CCP-02 / OPRP-05 ให้เองตามผลิตภัณฑ์ในทะเบียนจุดควบคุม (ขั้นตอนที่ไม่มีบันทึกเป็น N/A) ไม่ผ่านเปิด NCR ตรวจทุกค่าก่อนบันทึก จึงไม่มีการบันทึกครึ่งเดียว พบสิ่งปลอมปนเปิด NCR รายงาน A4 รายวันตามฟอร์ม พร้อมค่า Polar จาก FM-QC-005 |
| น้ำมันทอด FM-QC-005 (`/qa/oil`) | บันทึก TPM 1–3 ค่าและอุณหภูมิน้ำมัน ก่อน / ระหว่าง / หลังผลิต ระบบตัดสิน TPM: < 20% ปกติ, 20–<25% เฝ้าระวัง (ต้องบันทึกการประเมิน), ≥ 25% ห้ามใช้ (ต้องบันทึกสิ่งที่ทำ และเปิด NCR กักกันน้ำมัน) อุณหภูมิผู้ตรวจตัดสินตาม WI (N/A ต้องมีเหตุผล) QA ทวนสอบ APPROVE / REJECT รายงาน A4 รายเดือน |
| ตู้เย็น / ตู้แช่แข็ง FM-QC-006 (`/qa/cold`) | ทะเบียนตู้ (QA) พร้อมเกณฑ์ตาม SOP: Chill 0–5 °C Escalation > 8 · Freeze ≤ −18 °C Escalation > −12 ปรับให้เข้มกว่าได้ บันทึก 08:00 · 11:00 · 15:00 · 17:00 และตรวจซ้ำ รอบ 08:00 ต้องตรวจสภาพตู้ 6 ข้อ นอกเกณฑ์ต้องเลือกการดำเนินการและระบุสาเหตุ เกิน Escalation ต้องแจ้งหัวหน้างานและระบบเปิด NCR (HOLD ต้องระบุ Lot) บันทึกสถานะเทอร์โมมิเตอร์หมดอายุสอบเทียบ รายงาน A4 รายเดือนต่อตู้ |
| ค่า pH และ aw ผลิตภัณฑ์สำเร็จรูป (VER-01) | บันทึกต่อ Batch ทุกผลิตภัณฑ์ (pH, aw, อุณหภูมิขณะวัด aw, สถานะสอบเทียบเครื่องวัด, ที่วัด/เลขรายงาน) บันทึกค่าอย่างเดียวจนกว่า QA จะกำหนดเกณฑ์จาก Shelf life study ไม่ใช่เงื่อนไขการปล่อยสินค้า ดูย้อนหลังและ CSV ที่ `/qa/records` |
| สอบย้อนกลับ (`/qa/trace`) | ค้นด้วยเลขล็อตวัตถุดิบหรือเลข Batch: ใบตรวจรับ Batch ที่ใช้ล็อตนั้น บันทึกตรวจ และ NCR ที่เกี่ยวข้อง |
| สุขลักษณะส่วนบุคคล FM-QA-007 (`/qa/hygiene`) | ตรวจพนักงานก่อนเข้างาน 12 หัวข้อเดิม และเพิ่มข้อ 13 สุขภาพ/บาดแผล (ข้อสำคัญ) เลือกผ่าน/ไม่ผ่านทุกข้อ ไม่ผ่านต้องระบุการแก้ไข ข้อสำคัญไม่ผ่านต้องไม่ให้เข้าพื้นที่ผลิต ผู้ตรวจคือบัญชีที่เข้าสู่ระบบ บันทึกเก็บข้อความหัวข้อ ณ เวลาตรวจ พิมพ์รายงาน A4 รายวันได้ หัวข้อแก้ได้เฉพาะ QA รหัสและ Rev. ของทุกแบบฟอร์มตั้งที่ `FORMS` ใน `src/config.js` |

ตารางในฐานข้อมูลถูกสร้างหรือเพิ่มเองทุกครั้งที่ deploy หลังบ้าน (ขั้นตอน Apply database schema)
